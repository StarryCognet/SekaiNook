# 家庭积分审批流双端改造计划

## Context（背景）

当前 SekaiNook 中，家庭工作台的「任务打卡」是**点击即加积分**：`handleTaskSubmit`/`handleTask` 直接 `addLedgerRecord` 写入 `family_ledger` 并刷新余额，没有审批环节、没有角色区分、没有消息通知。

用户希望改造成「**小孩完成任务 → 家长收到消息 → 家长审批通过 → 积分入账**」的双端操控模式。已与用户确认的决策：

1. **角色区分**：设置页手动切换「家长 / 小孩」，存 localStorage（zustand 全局状态）。
2. **消息通知**：家长端「待审批」角标 + 列表，轮询刷新（本地模式与 Supabase 模式均可用）。
3. **审批范围**：只审批家庭积分（`family_ledger`）；阳光花园的阳光积分保持即时，不动。
4. **提交方式**：小孩端可点任务按钮发起打卡申请（pending）；家长端提交保持直接入账（approved）。

## 数据模型

**新增迁移** **`supabase/003_add_ledger_status.sql`**：

```sql
alter table family_ledger
  add column if not exists status text not null default 'approved';
create index if not exists family_ledger_status_idx on family_ledger(status);
```

* `status` 取值 `'pending' | 'approved' | 'rejected'`，默认 `'approved'` → 旧记录自动兼容，无需数据迁移。

* RLS 已有 anon 的 update 策略，无需新增策略。

* localDb 无 schema 概念，天然兼容（逻辑层兜底）。

## 文件级改动

### 1. `src/types/family.ts`

* 新增 `export type LedgerStatus = 'pending' | 'approved' | 'rejected';`

* `LedgerRecord` 增加 `status?: LedgerStatus`（可选，兼容旧数据）。

### 2. `src/api/familyLedger.ts`

* `addLedgerRecord(task, extra?, opts?: { status?: LedgerStatus })`：默认 `'approved'`，insert 时写入 `status` 字段。

* 新增 `fetchPendingRequests()`：`.eq('status', 'pending').order('created_at', { ascending: false })`。

* 新增 `approveRequest(id)` / `rejectRequest(id)`：`.update({ status }).eq('id', id)`。

* 新增 `resubmitRequest(id)`：`update({ status: 'pending' })`（驳回后重新提交，保留审计痕迹）。

* 新增 `calcApprovedBalance(records)`：过滤 `!status || status === 'approved'` 后求和。

* `getBalance()`：改为 select `amount, status`，JS 层用 `calcApprovedBalance` 过滤（localDb 的 select 忽略列名返回全行，天然兼容；避免 Supabase SQL 与 localDb 方言不一致）。

### 3. `src/store/useFamilyStore.ts`

* 新增 `role: 'parent' | 'child'` + `setRole`，持久化 key `sekainook_role`（仿 [useGardenStore.ts](file:///e:/Git/SekaiNook/src/store/useGardenStore.ts#L21-L34) 的 `loadState`/`saveState` 模式）。

* 新增 `pendingCount: number`、`refreshPending()`（拉 pending 数量）。

* 新增 `approve(id)` / `reject(id)` 动作：调用 api → 刷新 pendingCount + records。

* `loadLedger()` 改为单一数据源：拉 records，balance 由 `calcApprovedBalance(records)` 计算（避免双请求不一致），同时刷新 pendingCount。

### 4. `src/views/family/FamilyDashboard.tsx`（核心 UI 改动）

* **提交逻辑**：`handleTaskSubmit` / `handleTask` / `handleCustomTask` 统一带 `status: role === 'child' ? 'pending' : 'approved'`。

* **消息区分**：child 提交后提示「已提交打卡，等待家长审批」（含 pending 数量变化）；parent 保持原成功文案。

* **新增「待审批」Tab（仅 parent 显示，带 Badge 角标）**：渲染 pending 列表（任务名 / 金额 / 时间 / 备注 / 图片缩略图 / 通过·驳回按钮），通过后即时刷新余额与角标。

* **余额卡片**：新增提示「待审批 N 项」（N>0 且 parent 时显示）。

* **历史记录区**：每条记录加状态 Tag（已入账 / 待审批 / 已驳回；无 status 视为已入账）；rejected 项显示「重新提交」按钮。

* 轮询：parent 每 10s 刷新 pendingCount（`visibilitychange` 暂停、focus/恢复时立即刷新）；child 放宽到 15–20s 刷新 records。

### 5. `src/views/settings/SettingsPage.tsx`

* 新增「当前身份」卡片：Segmented 家长 / 小孩，读写 store 的 `role`，附一句话说明（家长可审批积分，小孩打卡需审批）。

### 6. `src/layouts/MainLayout.tsx`

* 订阅 `useFamilyStore`，仅 parent 时给「家庭工作台」菜单项加 `<Badge count={pendingCount}>` 角标。

## 不改动的部分

* 阳光花园（`src/views/garden/*`、`useGardenStore`）：阳光积分保持即时。

* 每周学习计划、图片上传（R2）、Settings 页其余内容。

## 验证步骤

1. `npm run dev`，本地（localDb）模式：

   * 设置页切「小孩」→ 点任务打卡 → 提示「等待家长审批」，余额不变，角标 +1。

   * 切「家长」→ 出现「待审批」Tab → 通过 → 余额/历史更新、角标清零；驳回 → 显示「已驳回」，「重新提交」可再次进入审批。

   * 旧流水记录仍显示「已入账」且计入余额。
2. 切到移动端宽度（375px）确认布局/交互正常。
3. `npm run build` 通过类型检查。
4. 若已配置 Supabase：执行 `supabase/003_add_ledger_status.sql` 后按上述流程验证一遍。

SekaiNook · 底部 Tab 栏

它不是「悬浮」，它是浮着长的占位条

你说：「软件底部 tab 栏虽然是悬浮但不完全是，底部的内容完全被遮挡了」。 我理解成两件事叠在一起：① 它长得像浮在内容之上（圆角胶囊、四周露背景、带阴影），但布局上是一条独占的硬条带； ② 屏幕最底部那一块（约 98dp，接近屏高的 12%）永远只显示背景，内容滚到底也进不去 —— 所以「底部的内容」被这块区域吃掉了。

先说结论（本节 04/05 有可视化对比）

App 端这一条底栏是 Scaffold.bottomNavigationBar，没有开 extendBody。这意味着它不是一个「浮在内容上的层」，而是从 body 里切走 98dp 的一条固定带：内容区的底边 = 胶囊的顶边，两边严丝合缝，中间的 32dp 只是列表自己的内边距。想要真悬浮，必须开 extendBody 并把胶囊做成半透明 —— 两件事缺一不可。

有一处我不敢替你定，放在最后一节（07）

我实测的是「内容滚不到胶囊下面」，没有测到文字被胶囊压住看不见。如果你手机上确实看见有字被盖住，那是另一回事（多半是某一页的底部内边距偏小），麻烦把那页截个图给我。

02 · 为什么说它是「假悬浮」

两端的做法一模一样：让位，而不是穿透

App / Flutter

Scaffold 里没有 extendBody

// main_shell.dart:169
child: Scaffold(
  // 换 Tab 时内容横向滑入淡出
  body: SlideFadeSwitcher(...),
  // 悬浮胶囊底栏
  bottomNavigationBar: SafeArea(
    top: false,
    child: AppNavBar(...),
  ),
  // ← 这里没有 extendBody: true
)

bottomNavigationBar 不给 extendBody 时是硬占位：body 的高度会被减掉栏高，内容区物理上到不了栏下面。名字里的「悬浮」只体现在画法（胶囊、圆角、阴影）上。

Web / React

用 padding 给自己垫底

/* MainLayout.module.css:11 */
--bottom-nav-space: 108px;

/* :245 （移动端） */
.content {
  padding-bottom: calc(
    var(--bottom-nav-space) + env(safe-area-inset-bottom)
  );
}

网页端的底栏是真 fixed 浮层，但内容区靠 108px 的底部内边距把自己推上去 —— 效果一样：内容不进入底栏所在的那条带。

一句话概括现状

视觉上是悬浮，布局上是占位。 两端都选了「把内容往上推」，而不是「让内容从栏底下穿过去」。所以你会在滚动到底时看到：最后一条内容停在栏顶上方 32dp，栏和屏幕底边之间那段也只能是背景。

在什么页面上感觉最强

  • 任务区 / 花园 / 设置这类长列表：每滚一屏都少 98dp，看完一条长列表要多滚一两下。
  • 底部正好是一张卡片的页尾：内容止于栏顶上方，下面一整块空背景，看起来像「内容没加载完」。
  • 矮屏手机（如 720dp 高）：98dp 占到 13.6%，比你我这台更明显。

顺带查到一处偏小的

通知页的列表底部内边距是 AppSpacing.lg（24dp），比其它页的 32dp 少 8dp：notifications_page.dart:424。都不算「被遮挡」，但它是全套页面里最贴栏的一条 —— 如果你说的遮挡出现在通知页，就是这里。

04 · 看一遍就懂了

现状 vs 真悬浮（滚动演示，会自动滚到底再滚回）

三台手机都是 390 × 844，几何按上面那张表 1:1 画的。看三件事：内容区的下边界在哪、滚到底时最后一条停在哪、内容能不能滑到胶囊下面去。

现状 · 硬占位内容区止于 746（胶囊顶边），滚到底最后一条停在 714，下面 98dp 永远是空的。
方案 A · 真悬浮（半透明）内容区铺到屏幕底（extendBody），内容从胶囊后面滚过去；滚到底时最后一条停在 738，仍完整可见。
方案 B · 穿透但不透明内容确实滑到胶囊后面了，但看不见 —— 滚动手感没变，只省掉「被切一刀」的观感。
列表内容 底栏胶囊 永远只显示背景的那块

为什么我强调「半透明」这一步不能省

下面的演示里，底下那几条内容位置完全相同，只改胶囊的透明度。开到不透明时，穿透等于没做 —— 内容确实过去了，但被挡住，用户感知不到任何差别。

三格看完，请注意一件容易被忽略的事

0.86 的白胶囊叠在浅色内容上，明度差只有几个百分点 —— 真机上几乎看不出「穿透」。上面三格之所以看得出差别，是因为我特意在演示里塞了一张深色卡（手机模型里每隔 5 条也放了一张）。

换算到真实页面：任务区、设置页基本都是白卡，方案 A 的透明收益接近于 0，真正拿到的是「内容能滚到栏下面」本身（多 98dp 可视高度）。你会明显感觉到透明，是在设了背景图、或列表里滚过深色/彩色卡片的时候。

一个硬约束：App 端不能用毛玻璃糊

最漂亮的解法是 BackdropFilter 毛玻璃（内容在栏背后被糊开）。但 1.31.8 你已经把它整套撤掉了 —— 真机实测滚动手感掉帧，网页端更吃力。所以方案 A 只能走半透明实色 + 细描边 + 轻阴影，不能退回模糊。（AGENTS.md：卡片一律走 AppCard，禁止 BackdropFilter 毛玻璃。）

05 · 三套修法

改什么、动几处、有什么代价

A · 推荐

真悬浮半透明

extendBody: true，各页底部内边距 32 → 106，胶囊底色改半透明（0.86）+ 细描边。

  • 得到：内容能从栏后面滚过去，一屏多 98dp，观感真正「浮」起来
  • 代价：胶囊文字对比度略降；页面内边距必须改准，漏一页那页最后一条会被栏压住
  • 改动面：1 处 Scaffold + 5~6 处列表内边距 + 1 处胶囊配色
B · 折中

穿透但不透明

只做 extendBody + 内边距，胶囊保持现在的白色实底。

  • 得到：去掉「内容被硬切在一条假边界上」的观感，滚动更连续
  • 代价：可视内容其实没多（滚到底仍要让位），悬浮感提升有限
  • 适用：你担心半透明后字发虚，先上这一档
C · 保守

不改布局，只做减法

保持硬占位，把占位压小、把压迫感去掉：内高 58 → 54、离底 8 → 6、阴影减淡、页内边距 32 → 24。

  • 得到：省回约 10~14dp，视觉上栏更轻
  • 代价：治标；那块区域依然进不去内容
  • 适用：暂时不想碰全局布局

我建议的顺序

  • 先 A。 你要的「真悬浮」只有 A 能给全 —— B 少了透明那一半，C 根本没解决。
  • 透明度的稳妥取法是 0.86：能透出底下有内容在动，图标与文字仍然清晰。先别一上来就 0.72。
  • 如果做完觉得字发虚，退到 B（只保留 extendBody 与内边距），不用整套回滚。

07 · 验收 与 需要你确认的

改完怎么算成

  • 滚动到底时，最后一条内容完整可见，不被胶囊压住任何像素
  • 滚动过程中，内容能滑到胶囊后面并透视出来（方案 A）/ 或至少滑到胶囊后面（方案 B）
  • 胶囊上的 5 个图标与文字在浅色主题 + 浅色内容下仍然清晰（对比度目测正常）
  • 五个 Tab 页（首页 / 家庭 / 花园 / 设置 / 计划）逐一滚到底检查，没有一页漏改内边距
  • 网页版窄窗口（< 560px）滚到底同样不被盖住
  • 矮屏（720dp 高）与高屏（900dp 高）各测一次

需要你确认的一点（这是我这页最想问你的事）

「底部的内容完全被遮挡」我读成了 ① 内容滚不到栏下面，那块区域永远进不去。如果你实际遇到的是 ② 有文字/按钮真的被胶囊盖住看不见，那修法完全不同 —— 那是个 bug（某页内边距不够或某个固定定位元素算错了高度），不用动全局布局。

告诉我是 ① 还是 ②；如果是 ②，把那页截图给我，我直接定位到行。

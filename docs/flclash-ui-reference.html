01

FlClash 的设计是什么

Material You · 超椭圆几何 · 描边图标 · 弹簧物理

FlClash 的 UI 不是“好看的颜色搭配”，而是四层确定性： 几何上全站只用超椭圆（squircle）一种曲率； 色彩上由一个种子色推导出整套 Material You 色调； 图标上用描边→填充表达状态而不是换图标； 动效上用手感参数统一的弹簧而不是时间曲线。 这四件事叠起来，才是它“一眼高级”的来源。

超椭圆几何

全站禁用圆角矩形。RoundedSuperellipseBorder 统一 8 档圆角，小控件按最短边自动降档。

动态取色

用户选一个种子色，HCT 推导出 30+ 语义色，亮/暗/纯黑三套自动生成，语义色还会 harmonize 到主色。

图标即状态

自定义 Glyph 体系：未选中是 1.8px 描边、选中填充实心，同一套 path 用 fill-opacity 交叉淡入。

弹簧物理

导航落位用 bounce: .32 的弹簧、按下用 bounce: .2，配合 100/200/300ms 三档时长。

03

图标体系

FlClash 不用 Material Icons。它自己做了一套 Glyph：24×24 视口、1.8px 描边、圆头圆角， 未选中是空心线稿、选中直接填充为实心——用同一份 path，靠 fill-opacity 从 0 到 1 过渡。 这套做法让“状态变化”变成一眼可读的视觉信号，而不是换个颜色。

3.1 状态：描边 ↔ 填充点任意图标切换
24 × 24 viewBox stroke 1.8 round cap / join fill-opacity 0 ↔ 1 同一份 SVG path，选中时只是把填充打开 —— 这是 AnimatedGlyph 的核心。
350ms / easeInOutCubic

填充从 0 到 1 的时长与曲线，和 Material 的图标切换同量级。

1.8 → 2.2 自动加粗

整枚都是线的图标（没有可填充的面）切到填充态时会把线加粗到 2.2，靠这点粗度假装出「实心」。

胀一下：sin(πt) × 0.1

过渡中间整个图标放大 10% 再回来，幅度小到说不出哪里动了，但手感「弹」。

detail 在 0.5 处翻转

填充过半时，原本填充的 body 挖空、原本挖空的 detail 补上 —— 所以中间有一帧是接近剪影的。

4.9 渲染出来才看得见的九个细节Apple 味就藏在这里

前面几节是「长什么样」，这一节是「为什么手感对」。这些地方没人在设计稿上画得出来， 但每一个都是 FlClash 和普通 Flutter 应用的差距所在。

滚动条是自己画的 不是系统滚动条

静止 6px，悬停或拖动时涨到 10px 且颜色变深；最短 48px（再短抓不住）。松手后 250ms 淡出、但要等 1.2 秒才彻底消失 —— 注释原话是「够你松手再抓回来」。拖到侧面还能变速：离轨道 48px 内速率 [1, .5, .25, .125]，横向拉得越远滚得越慢，并且主动关掉甩动惯性。触摸平台直接不显示。

动效实验室

第 09 章是「参数表」，这一章是「上手玩」。下面这些演示里的弹簧不是 CSS 曲线近似—— 用的是 Flutter SpringSimulation 的同一套解析解，参数由 SpringDescription.withDurationAndBounce(duration, bounce) 现场换算。 按下去、拖出去、松手，看它怎么回来。

11.1 先看引擎：一次回弹到底在算什么拖滑块改参数
弹簧曲线—
虚线是终点 1.0。曲线末端被拉平到 1 —— 这正是 SpringCurve 的做法： 弹簧只播前 0.50 秒，剩下的残差按 residual × t 线性摊到尾部， 所以它既能过冲、又保证 100% 落在终点。
参数withDurationAndBounce
duration500ms
bounce0.32
换算只有三行：stiffness = 4π²·m / duration²、dampingRatio = bounce > 0 ? 1 − bounce : 1/(bounce+1)、 damping = ratio · 2√(m·stiffness)。bounce = 0 时是临界阻尼（最快停住且不过冲）， bounce 越大越像果冻 —— 这就是为什么 FlClash 全站只用「时长 + 回弹」两个词描述弹性，而不是让开发者填劲度系数。
11.2 底部 dock：按下、拖出去、松手真的可以拖
lens 0.00 velocity 0.0 swell 0.00 stretch 0.0 pressed — dragging no
用手或鼠标按住再横向拖。按下时整条 bar 与透镜一起鼓起来 —— 注意它只放大约 4%： 膨胀量被公式封顶在 16px（min(2/8, 16/最长边)），条越宽比例越小，所以 dock 是「微微一胀」而不是弹起来。 拖过边界由橡皮筋拉住，松手按 100ms 速度投影落格（最多越一格）；鼠标横掠还有 iPad 那种「高亮吸过去一点」的 hover。

对比：Material 水波纹同一只手感完全不同
点我（Material 水波纹）
水波纹是装饰：它从触点扩散，但按钮本体一动不动，松手瞬间结束。 果冻是物理：形变跟着手指走，松手还有回弹 —— 两个放一起按一下，差别立刻出来。 FlClash 全站 splashFactory: NoSplash，一滴水波纹都没有。

pointer down整条鼓起来 + 透镜立刻弹向按下那一格（松手前它不会中途跳）lift 280ms bounce .2 ／ lens 500ms bounce .32
move < 18px当作抖动忽略 —— 手指稍微歪一点不会把「点击」变成「拖拽」kTouchSlop = 18
move ≥ 18px进入拖拽：透镜贴着手指走，且带初速度地追（所以快速划动时它被拉长）lens / stretch 均 120ms 无回弹
拖出边界越界位移过一条软化的橡皮筋：越拖越重，但永远拖不出 最短边 × 7/32limit × (1 − 1/(|o|·0.55/limit + 1))

弹簧是带初速度重定向的 最容易被忽略的一条：FlClash 没有用 AnimationController.animateWith，而是自己写了一个持久弹簧 （_Spring，navigation_dock.dart:112）。原因是控制器每次重定向都会重启 ticker， 首帧读到的 elapsed 是 0 —— 于是手指一直在动时，值会卡住不动。它的做法是把「当前值 + 当前速度」喂给新的 SpringSimulation，并且只重置时间基准、不打断 ticker。

bounce ≠ 过冲率 这是最容易读错的一个数。Flutter 的换算在 spring_simulation.dart:70-82： dampingRatio = bounce > 0 ? 1 - bounce : 1/(bounce+1)， 所以 bounce 0.32 的 ζ 是 0.68，过冲只有 5.4%（exp(−πζ/√(1−ζ²))）； 真正弹的是 bounce 0.55 → ζ 0.45 → 过冲 20.5%。把 bounce 当百分比读会高估六倍。
反例：长按不是弹簧 FlClash 桌上版「长按」缩到 0.95，但那是 AnimatedScale + 200ms easeOut（lib/widgets/effect.dart:8）， 不是弹簧；同一文件里还有一个创建后从未使用的 AnimationController。 而且全站触觉反馈只有 4 处 —— 长按拖拽全程零震动，只在 dock 跨格与抛掷落点各响一下 selectionClick()。
11.6 这个复刻哪里不像诚实说明
染色用矩形裁剪近似

原版把每个格子的内容画两遍：透镜外用 onSurfaceVariant、透镜内用 ColorFilter.mode(primary, srcIn) 重绘，两条路径用 evenOdd 按透镜轮廓精确互斥（_RenderLensTint.paint）。这里用双绘 + clip-path: inset() 矩形裁剪近似 —— 「同一行字一半一个色」是对的，只是圆角接缝处会差几个像素。

触觉只能靠 vibrate

HapticFeedback.selectionClick() 在网页里退化成 navigator.vibrate(8)，桌面浏览器无效、iOS Safari 直接不支持 —— 手感最接近的是安卓 Chrome。

帧率不同

Flutter 侧由 vsync 驱动（60/120Hz 固定步长语义），浏览器是 rAF。弹簧用的是解析解而不是逐帧积分，所以曲线本身一致，只是采样时刻不同。

悬停行为是桌面专属

原版只在非触摸指针上启用 hover 高亮（注释写明：引擎会在触摸落点前合成一次 hover，不排除的话点一下高亮就留在那儿了）。这里同样只对鼠标生效。

11.7 搬回 SekaiNook：差距不在弹簧，在「按压往哪边走」逐文件比对

把两边源码摊开对比之后，结论有点意外：底座是同源的。 SekaiNook 的 SpringDriver（app/lib/ui/widgets/motion/spring_driver.dart:7） 连「为什么不用 AnimationController.animateWith」这条注释都和 FlClash 的 _Spring 一致， app/lib/theme/motion.dart 的弹簧参数也明确注了取自 navigation_dock.dart:62-79。 真正不同的是三个设计选择。

这一项FlClashSekaiNook 现状差在哪
弹簧驱动器 自建 _Spring（navigation_dock.dart:112），重定向只改时间基准 已对齐：spring_driver.dart:11 已一致
跟手／橡皮筋／速度投影 dock 内三套齐全（_trackSpring 120ms、7/32 极限、100ms 投影） dock 已有（app_nav_bar.dart 的 jelly／透镜／橡皮筋） 已一致
按压缩放方向 放大 1 + min(25%, 16/最长边) + 位移拉伸 缩小 到 0.97（motion.dart 的 pressScale） 相反
水波纹 全站 NoSplash，按压只由形变表达 app_theme.dart 里 splashFactory: InkSparkle 相反
拖拽位移是否跟手 有：_pullX/_pullY 各自橡皮筋，按下后能拖出去 无：PressScale 只做缩放 缺
触觉频率 只在 dock 跨格、抛掷落点各一次 selectionClick() 每次点按 HapticFeedback.lightImpact() 偏多
dock 透镜着色 evenOdd 双绘：透镜内染 primary，划过时半行变红 纯色胶囊（当初不做是因为「blur 太贵」） 缺，但它不用 blur
① 一行去掉水波纹

app_theme.dart 里 splashFactory: InkSparkle 改成 NoSplash.splashFactory，并把各页 InkWell 的 overlay 设为透明。这是投入最小、观感变化最大的一步 —— 水波纹一消失，弹簧形变才成为唯一的按压语言。

② 让按压「长」而不是「缩」

把 PressScale 从 0.97 换成 FlClash 的 1 + lift × min(0.25, 16/最长边) 并加上非均匀拉伸（scaleX 用宽归一、scaleY 用高归一）。注意这是审美分歧：Apple 系（含 SekaiNook 现在）按下去是缩，FlClash 是鼓起来 —— 建议先做成可切换，真机对比后再定。

③ 透镜染色不是毛玻璃

当年回滚的是 BackdropFilter；这个效果用的是 ClipPath + ColorFilter.mode(primary, srcIn) 的双绘（照 _RenderLensTint.paint），一次 GPU 路径、不采样背景，不吃性能。这是 dock 从「像」到「是」的最后一步。

④ 触觉降到「只在有意义的地方响」

把每次点按的 lightImpact 收掉，改成只在 dock 跨格与抛掷落点各响一次 selectionClick。震动一多就不值钱 —— FlClash 全站只有 4 处。

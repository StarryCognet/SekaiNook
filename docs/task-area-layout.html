任务区排版优化：从「12 个实色按钮」到「一张能读的清单」

乱的不是信息量，而是表达方式：12 条任务被渲染成 12 个全宽高饱和实色按钮（绿 7 + 红 5），塞进同一张白卡里， 色块本身就是内容，分组标签反而最轻；做完的任务只从彩色变灰、继续占位； TaskConfig 里已有的时间窗 / 日限 / 说明一个都没露出来。 下面按「现状 1:1 复刻 → 4 套排版方案 → 统一任务行规范 → 逐条落地位置」展开，所有 mockup 都是按 Flutter 实际尺寸画的（1px = 1dp）， 并可在右上角切换 4 个出厂主题预览。

核心结论把「实色按钮」降级为「清单行」，颜色退回到语义提示（图标块 / 分值），首屏色块数从 12 降到 0。
结构结论只摊开今天没做完的，完成项收进「今日已完成 N 项」折叠区；分类用子卡或分段控件，而不是红绿两列。
信息结论行内补回已有但没显示的字段：日限 1/2 次、时间窗 19:00–22:00、说明（保护眼睛）。

  3. 3语义错位。「看 iPad 30 分钟」是一次正常记账，却用 palette.danger 铺满整行底色 —— 孩子点下去像在触发事故；而「罚款」这类真正要慎重的项，视觉权重与普通消费完全相同。
  4. 4层级颠倒。分组标签 14px / textSecondary，比按钮文字（14px 白字 on 实色）弱得多；分类信息本该是导航级信息，现在是最弱的元素。
  5. 5完成态淹没列表。做完只换 disabled 样式（底 surfaceSoft、字 textTertiary），仍占原位。下午打开列表时，剩下的待做任务被一堆灰块埋在中间。
  6. 6没有进度锚点。任务区看不到「今天 x/y」；进度只在首页 todayProgress() 与「今日任务与作息」卡里。用户必须切页面才知道还剩多少。
  7. 7已有字段没露出来。TaskConfig 自带 window（按时睡觉 19:00–22:00）、dailyLimit（整理房间 2 次 / 洗 iPad 4 次）、description（视力下降1度：保护眼睛），行内一个都看不到；用户只能靠点下去被拒后才知道规则。
  8. 8对齐不稳。按钮内是 Icon + Expanded(name) + value，分值列跟着名字长度浮动；按钮高度由 M3 FilledButton 默认值决定（40dp），与卡片 16px 栅格、其他列表行不同拍。
  9. 9家长端表单常驻。「类型 / 价格 / 名称 / 添加」四段垂直堆叠 + 任务列表长期占据任务区下半屏；且白底表单与上方满色卡风格割裂。Web 版已把这块收进折叠。

移动端差异点（本次要重新决策的地方）

  • Web 桌面用 1fr 1fr 双列；手机是 1fr 单列 —— 手机上「双列」不是选项，所以分组必须靠标题 + 子卡而不是左右两列。
  • 按钮高 44 → 48dp、字号 14 → 16px。在 390dp 宽的手机上，48dp 实色按钮的视觉重量比桌面大得多（占宽 100%、面积占比约 12%）。
  • Web 版有 hover / 光标暗示可点；移动端只能靠形状与文案，所以行样式必须自带「可点」语义（勾选圈 / 按钮高亮）。
结论

本次迭代的目标可以一句话概括

把 Web 端的「结构」（只摊未完成 + 完成折叠 + 管理收起）搬到 Flutter， 再把两者共同的「行样式」从实色按钮改成清单行 —— 顺带把 Flutter 端三处各不相同的任务行统一成一套。

一张卡里再放卡片必须换底：外层卡白底 + 1px 描边；内层分组用 surfaceSoft 底、去掉描边，否则三张一样的白卡叠起来又变成「看不出层级」。 任务行本身用 surface 底 + 描边（在软底分组里）或 surfaceSoft 底（在白卡里），二选一，不要同时用底色和描边表达两件事。

为什么不是「一个任务一个大按钮」了

实色按钮是「动作」的视觉语法，适合一屏 2–3 个决策点；任务区是「列表」的语法，一屏 12 条。 把列表项做成按钮，等于把 12 个平级动作都喊成同一音量 —— 这正是「乱」的感受来源。 改成清单行之后，动作语义由状态圈 + 整行可点承担，颜色只承担语义标注，两者不再互相打架。

  • 不要继续加颜色。用更多色相区分任务类型只会更花；分类靠分组标题，语义靠分值正负。

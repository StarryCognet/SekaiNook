## 1. 这个项目是什么、怎么跑

- **SekaiNook**：家庭积分账本 PWA。孩子打卡赚积分、家长审批；另有「花园」（学习乐园）子系统。
- 技术栈：React 18 + TypeScript + Vite + antd（前端）／ Cloudflare Pages Functions + D1（服务端）／ R2（图片）。
- 工作目录：`E:\Git\SekaiNook`。线上：`https://sekainook.pages.dev`。
- **服务端与前端各有一份规则表，必须同步改**：`functions/_lib/rules.ts`（服务端唯一可信源）与 `src/config/familyRules.ts`（前端）、花园部分加 `src/config/garden.ts`。
- 常用命令：`npx tsc --noEmit`（类型检查）、`npm run build`（构建，改完必须 exit 0）。

## 6. 已知风险与坑（**务必读**）

1. **线上 D1 没有 migration 执行通道**：`functions/` 下只有 `api/`（无 `scheduled` handler），线上建表/改表只能用户手工跑 SQL。**所以整个 v1.30 不新增表、不新增列** —— 自定义任务存 `localStorage`，罚款靠固定 id + `INSERT OR IGNORE` 幂等。若后续有人提「加个任务表」，先想清楚这条约束。
2. **没有定时任务**：罚款不是「22:00 准点扣」，而是**下次打开页面时结算**（`POST /api/ledger/settle`，前端节流）。文案不能写成「立刻扣」。结算日 `≥22:00 ? 今天 : 昨天`，罚款 `created_at` 回填到被结算日正午，否则会污染「当日完成数」的 `created_at` 过滤。
3. **文件冲突**：task-3 与 task-4 都改 `FamilyDashboard.tsx`、`KidHome.tsx`。规则：写前重读、最小替换、禁止整文件重写与格式化；遇 STALE/冲突就重读后重贴改动，不要盲目重试同一写。
4. **「添加任务」绝不能再变成即点即入账** —— 需求 5 要否掉的就是这个（现状在 `FamilyDashboard.tsx` 的 `handleCustomTask`）。
5. **孩子自加任务必须走 pending**（`autoApprove:false`），否则是刷分口子。
6. **未知 `task_id` 现在一律 403** —— 前端不能再自造 id 写账本。
7. **「阳光」不要全站清掉**：只改算钱处；栏目名/比喻/注释保留（用户明确选择）。剩约 60 处开发者注释是刻意保留的（它们解释「花园阳光 vs 家庭积分」两本账的区别）。
8. **文档路径坑**：用文件工具写含转义序列的文件名会生成 `docs/v1.30-/u9700/...` 这种垃圾目录（我踩过，已清理）。**新建文档请用纯 ASCII 或已存在的中文路径**，写完 `ls docs/` 确认落点。
9. **changelog 日期要真实**：项目历史上因日期乱写（甚至写成未来）被用户要求订正过一次（提交 `197033f`）。

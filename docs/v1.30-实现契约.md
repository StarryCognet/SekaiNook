# v1.30 实现契约（所有实施者必读，禁止偏离）

> 需求方案见 `docs/v1.30-需求方案.md`。本文件是**接口级契约**：跨文件的常量、id、字段名、口径必须与此完全一致，否则合并后会出现「两边算出来的数不一样」。

## 1. 硬约束

- **不加表、不加列**：线上 D1 没有 migration 执行通道（`functions/` 下只有 `api/`，无 scheduled handler），线上 SQL 只能用户手工跑。任何方案若需要新表/新列，即视为不可接受。
- **服务端是唯一可信源**：`functions/_lib/rules.ts` 定分值/日限/窗口/是否自动到账；客户端传的 `status` 一律忽略。
- **改规则必须同步两处**：`functions/_lib/rules.ts` 与 `src/config/familyRules.ts`（花园部分加 `src/config/garden.ts`）。
- 只允许改自己任务写在 `write_scopes` 里的文件。

## 2. 唯一 id 常量（写死，不得改名）

| 用途 | task_id / 记录 id | 金额 | 备注 |
|---|---|---|---|
| 开户礼金 | `seed_welcome_bonus` | `+100` | 一次性，服务端生成，`serverOnly` |
| 日结算罚款（不足 5 个任务） | `daily_min_tasks_penalty` | `-10` | id 为 `daily_penalty_<YYYY-MM-DD>`，`serverOnly` |
| 睡觉罚款 | `sleep_penalty` | `-20` | id 为 `sleep_penalty_<YYYY-MM-DD>`，到 22:00 未打卡 |
| 预置任务・英语 | `custom:english_words10` | `+10` | 名称「十个英语单词」，日限 1 |
| 预置任务・古诗 | `custom:poem2` | `+10` | 名称「两首古诗」，日限 1 |
| 自定义任务打卡（统一执行 id） | `user_task_exec` | 客户端传（夹 -200~200） | 名称由客户端带（`clientName`），**三层闸门见 §4.1** |
| 睡觉打卡 | `sleep_on_time` | `+10` | 窗口改 `19:00`–`22:00` |

- `<YYYY-MM-DD>` 一律取**东八区**日期（用 `functions/_lib/rules.ts` 的 `beijingClock`）。
- 自定义任务本地 id：家长 `custom_<Date.now()>`、孩子 `wish_<Date.now()>`；预置任务本地 id 与 task_id 同名。

## 3. 「今日完成数」口径（两端必须一致）

东八区当日、`status IS NULL OR status='approved'`、**`type='earning'` 且 `amount > 0`** 的流水，按 `task_id` **去重**计数；排除 `seed_welcome_bonus`、`daily_min_tasks_penalty`、`sleep_penalty` 三条系统记录。

- 一天背三首诗只算 1 个任务（与 v1.29 修的「11/8」同口径）。
- 花钱/罚款不算完成。
- 阈值 `DAILY_MIN_TASKS = 5`、罚款额 `DAILY_MIN_TASKS_PENALTY = 10`，两端各自定义但值必须相同。

## 4. 前端 store 契约

新文件 `src/store/useCustomTasksStore.ts`，localStorage 键 `sekainook_custom_tasks_v1`：

```ts
export interface CustomTask {
  id: string;
  name: string;
  value: number;              // 完成可得（正）/ 需扣（负）
  type: 'earning' | 'spending';
  createdBy: 'parent' | 'child';
  createdAt: string;
  kind: 'preset' | 'custom';
  repeatDaily: boolean;       // 默认 true
}
```

导出（名字固定）：
- `useCustomTasksStore` — React store：`tasks`、`doneDate`（记录每个任务最后完成日）、`addTask(input)`、`removeTask(id)`、`ensurePresets()`、`markDone(id)`、`isDoneToday(id)`。
- `selectPresetTasks()`、`CUSTOM_TASKS_KEY`、`PRESET_TASK_IDS`。
- 完成数口径辅助：`countDoneToday(records, now)`（或复用 `src/utils/taskRules.ts` 的等价实现）。

`src/api/familyLedger.ts` 新增：
- `settleLedger(): Promise<{ family: number; sun: number; applied: string[]; day: string } | null>` — POST `/api/ledger/settle`，失败不抛（返回 null 或静默）。
- `LEDGER_SETTLE_PATH = '/api/ledger/settle'`。
- 结算路由**只导出 `onRequestPost`**（不得导出 PATCH/DELETE），避免与动态路由 `functions/api/ledger/[id].ts` 在同一路径产生方法级重叠。

### 结算日（settleDay）规则 —— 已批准 server-dev 的 C 方案

- `settleDay = (东八区现在 ≥22:00) ? 今天 : 昨天`；开户按「账本无任何真实用户流水」判断。
- 睡觉罚款与「不足 5 个任务」罚款**都判 settleDay**，记录 id 与 `created_at` 都回填到 settleDay 正午（东八区）。
- **正确性完全由服务端幂等 id 保证**（`daily_penalty_<settleDay>` / `sleep_penalty_<settleDay>` 先查存在即返回）。前端节流只为省流量，**不得承担正确性**。
- 不允许「当天没过完就扣」：`settleDay === 今天` 只在 ≥22:00 时成立，故天然安全。

### 服务端额外约束（server-dev 已实现，其余各组须知）

- `seed_welcome_bonus` 与 `daily_min_tasks_penalty` 标 `serverOnly: true`：客户端 POST 它们也一律 403（否则 seed 会成为「每天白拿 100」）。
- `user_task_exec` **负数记成 `spending`**，保持不变量：`earning ⇒ amount>0`、`spending ⇒ amount<0`（`calcApprovedBalance` 与 `amountText` 都依赖它）。
- `user_task_exec` 缺 `amount` 时**必须 400 拒绝**，不得静默记 0 分。
- **未知 `task_id` 一律 403**（`functions/api/ledger/index.ts`）：前端**绝不能**再用 `custom_<ts>` 之类自造 id 直接写账本。

### §4.1 自定义任务的三层日限闸门（task-1 定稿，全部 409）

| 闸门 | 条件 | 文案 |
|---|---|---|
| ① 同名判重 | 同一 `task_name`（用**即将写入的 `finalName`**，已 trim + 折叠空白 + 截断 30）当日 ≥1 | 「「X」今天已经打过卡啦」 |
| ② 条数粗闸门 | 当日 `user_task_exec` 条数 ≥ `dailyLimit`(20) | 「今天添加的自定义任务已经够多啦（每天最多 20 个）」 |
| ③ 正分总额 | 当日 `user_task_exec` 正分累计 ≥ `CUSTOM_TASK_DAILY_CAP`(50)，只算 `status != 'rejected'` 且 `amount > 0`（**pending 也占额度**，否则连点可绕过） | 「今天的自定义任务积分已经拿满啦（每天最多 50 分）」 |

- 判重用**写入同源的规范化值**，所以「  倒垃圾  」带空格重发同样 409。
- 预置任务 `custom:english_words10` / `custom:poem2` 是**各自独立 id、各自日限 1**，同一天两条都能打卡、各 +10，且**不占**上面那 50 分额度。
- 被封顶拒绝的记录不落库；被日限拒过的路径上，已有 id 重发仍走幂等分支（`duplicate: true`）。

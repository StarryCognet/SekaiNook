# v1.30 方案：七条需求（积分体系重做）

> 状态：已与用户确认语义（用户答复：①A ②A ⑤⑥「A、B 都要」 ③④A ⑦B；后续两问：只统计算钱口径、日结算走服务端幂等接口）。
> 硬约束：**不加表、不加列**（线上 D1 没有 migration 执行通道，`functions/` 下只有 `api/`，无 scheduled handler，线上 SQL 只能用户手工跑）。

## 需求与实现口径

| # | 用户需求 | 落地口径 |
|---|---|---|
| 1 | 默认 100 积分 | 全新账号（账本里连一条「开户」记录都没有、且无任何其他流水）首次打开时，幂等写入一条 `+100` 的 `seed_welcome_bonus` 流水，`autoApprove`，一次性 |
| 2 | 每日至少完成 5 个任务，否则扣 10 积分 | 新增服务端日结算：某天完成数（去重任务数）< 5 时写一条 `-10` 的 `daily_min_tasks_penalty`，幂等 id 保证一天只扣一次 |
| 3 | 余额改为积分 | 只统一**算钱口径**：余额 / 奖励 / 罚款 / 商城价格 / 概览统计一律叫「积分」；「阳光花园」「阳光商城」等栏目名与装饰性文案保留 |
| 4 | 添加积分收益兑换机制 | 兑换＝花园商城（同一货币后即是「积分换礼物」）；家庭页的「结算兑现」保留为现金兑现出口 |
| 5 | 「添加任务」不进账，只进任务列表 | 家长与孩子两端都把 `addLedgerRecord` 换成「写入自定义任务列表」；点击完成打卡时才入账 |
| 6 | 十个英语单词、两首古诗各 10 积分加进任务列表 | 两条预置任务：`custom:english_words10`（十个英语单词，10 分）、`custom:poem2`（两首古诗，10 分），默认出现在任务列表 |
| 7 | 睡觉改成十点之前 | `sleep_on_time` 窗口 19:00–**22:00**；到 22:00 未打卡自动记 `-20` 罚款（`sleep_penalty`，幂等） |

## 服务端设计（唯一可信源 `functions/_lib/rules.ts`）

### 新增规则

```
'custom:english_words10': { name:'十个英语单词', type:'earning', value:10, dailyLimit:1, autoApprove:true, clientAmount:{min:1,max:100} }
'custom:poem2':           { name:'两首古诗',     type:'earning', value:10, dailyLimit:1, autoApprove:true, clientAmount:{min:1,max:100} }
'user_task_exec':         { name:'自定义任务',   type:'earning', value:0,  dailyLimit:1, clientAmount:{min:-200,max:200} }  // 名称由客户端带
'daily_min_tasks_penalty':{ name:'今日完成不足 5 个任务', type:'spending', value:-10, dailyLimit:1, autoApprove:true }
```
- `custom:*` 是**预置学习任务**：分值固定 10（`clientAmount` 只为兼容老客户端/未来调分，实际按 value），当日限 1 次，打卡即到账。
- `sleep_on_time` 窗口改 `{start:'19:00', end:'22:00'}`。
- `sleep_penalty` 名字改「未按时作息(晚于22:00)」，保留 `-20 / dailyLimit 1`。
- ⚠️ **堵空洞**：现 `functions/api/ledger/index.ts:85-96` 对未知 `task_id` 只要客户端带齐 `task_name/type/amount` 就放行，且 `dailyLimit === undefined` 时跳过限次判断 ⇒ 可无限自报金额刷分。改为：**未知 `task_id` 一律 403**；自定义任务走 `user_task_exec`（有 dailyLimit + clientAmount 夹取）。

### 幂等 id（服务端生成，客户端不用管）

- 开户：`seed_welcome_bonus`
- 日结算：`daily_penalty_<东八区 YYYY-MM-DD>`
- 睡觉罚款：`sleep_penalty_<东八区 YYYY-MM-DD>`

三条都由服务端接口内部 `INSERT OR IGNORE`，重复调用天然幂等（主键冲突走 `duplicate: true` 分支）。

### 新接口 `POST /api/ledger/settle`（日结算）

请求体 `{}`（可选 `{date?: 'YYYY-MM-DD'}`，仅测试用）。逻辑，全部按东八区当日：

1. **开户**：若 `family_ledger` 中 `id = 'seed_welcome_bonus'` 不存在，且不存在任何「真实用户流水」，插入 `+100`。（避免老账号凭空多 100。）
2. **睡觉罚款**：若东八区现在 ≥ 22:00（或本次结算的是过去某天），且当日没有 `sleep_on_time` 的**已通过**记录，插入 `-20` `sleep_penalty`（幂等 id）。
3. **每日不足 5 个**：当日「已完成任务数」< 5 时插入 `-10`（幂等 id）。完成数口径见下。

响应：`{ family, sun, applied: string[] }`（`applied` 说明这次实际记了哪几条，便于前端提示与排查）。

**完成数口径（必须与前端一致）**：东八区当日、`status IS NULL OR status='approved'` 的流水里，按 `task_id` 去重计数，**只看赚钱任务**（`type='earning'` 且 `amount > 0`），并排除三条系统记录（`seed_welcome_bonus` / `daily_min_tasks_penalty` / `sleep_penalty`）。理由：一天背三首诗只算一个任务（与 v1.29 修的「11/8」同一口径），花钱不算完成。

### 前端触达

- `src/api/familyLedger.ts` 新增 `settleLedger(): Promise<LedgerSettleResult>`；失败静默（不能因为结算失败挡住页面）。
- 首页（孩子 / 家长）与花园布局在 `loadLedger()` 成功之后调用一次，本地按「东八区日期」节流（当天已结算过就不再调）。
- 结算有实际入账（`applied.length > 0`）时：重新 `loadLedger()` 并给孩子端弹一条提醒（罚款要说清原因）。

## 自定义任务存储（不加表）

存本地 `localStorage`，键 `sekainook_custom_tasks_v1`。结构：

```ts
interface CustomTask {
  id: string;        // `custom_${Date.now()}`（家长）/ `wish_${Date.now()}`（孩子提的）
  name: string;      // ≤20 字
  value: number;     // 完成可得积分（正）或扣除（负），绝对值 ≤200
  type: 'earning' | 'spending';
  createdBy: 'parent' | 'child';
  createdAt: string; // ISO
  kind: 'preset' | 'custom';   // preset = 十个英语单词 / 两首古诗
  repeatDaily: boolean;        // 默认 true：每天可再打卡一次
}
```

- 新文件 `src/store/useCustomTasksStore.ts`：`tasks / addTask / removeTask / markDone / ensurePresets / isDoneToday`。
- 打卡入账：`addLedgerRecord({id:'user_task_exec', name: task.name, type: task.type, value: task.value, unit:'积分'}, …, {autoApprove: true})`，本地记「今日已完成」。
- 两条预置任务（`custom:english_words10` / `custom:poem2`）在首次运行时自动写入（`ensurePresets`），**不进账本**，只出现在任务列表。
- 孩子端 `createdBy:'child'` 的任务：完成时能打卡，但入账走 `pending`（家长审批）——与「孩子自己加待办，完成后给分需家长确认」的答复一致。

## 风险

- 「实时扣除」不可得（Cloudflare Pages 无 scheduled handler）：罚款在**下次打开时**补记，且记账时间戳允许回填到被结算那一天（否则「当日完成数」按 created_at 过滤会算错）。这是必须写进实现的细节。
- 孩子端「自己添加」若也走 autoApprove 会变成刷分口子 ⇒ 必须走 pending。

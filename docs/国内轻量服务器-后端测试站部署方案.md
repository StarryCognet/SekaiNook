# 国内云后端测试站 · 部署方案（2C4G / IP + HTTP / D1 快照）

> 目标：在服务器 2C4G 上跑一份 SekaiNook 后端的**可测试镜像**，验证国内访问速度。
> 约束：Cloudflare 线上后端**零改动、继续作为唯一真源**；测试站数据来自线上 D1 的一次快照，
> 单向复制、绝不回写；访问方式 `http://<服务器公网IP>`（无备案域名）。
>
> 本文是执行清单，不是已实施记录。按 §10 的顺序做，预计半天。

---

## 1. 边界：做什么、不做什么

| | 内容 |
|---|---|
| 做 | 现有 `functions/` 全部业务代码原样跑在 Node 上；nginx 服务 Flutter Web 产物；SQLite 替代 D1；本地目录替代 R2 |
| 不做 | 不碰 CF 的 `wrangler.jsonc` / D1 / R2 / Worker；不把测试站数据回写线上；不做 Web Push；不做 App 更新清单；不做小程序 |
| 交付后 | 停服务 + 关安全组即完全撤销，线上无感 |

**为什么可行（已核对代码）**：后端对 CF 专有能力的依赖面极窄 ——

| CF 原语 | 代码里的实际用法 | 替代 |
|---|---|---|
| D1 | `prepare/bind/all/first/run/batch` + `meta.changes`；`raw()` 0 次 | better-sqlite3 包一层（约 120 行） |
| R2 | `get/put/delete/list({prefix,limit,cursor})`；无 multipart、无预签名 | 本地目录（约 80 行） |
| Pages 上下文 | `context.env/request/params/next()`；**无 `waitUntil`、无 KV/DO/Queue** | 十几行适配 |
| 运行时全局 | `Response.json`(144 处)、`crypto.randomUUID/subtle`、`fetch/Headers/URLSearchParams` | Node 22 原生全有 |
| 前端 | `apiBase` 是 `String.fromEnvironment('API_BASE')` | 构建时 `--dart-define` 切换，**客户端零改动** |

SQL 方言也是纯 SQLite：只有 `ON CONFLICT`(11) 与 `RETURNING`(2)，better-sqlite3 内置的 SQLite ≥ 3.42 直接支持。

## 2. 目标架构

```
手机 / 浏览器
   │  http://<服务器IP>:80
   ▼
nginx ── /                → /opt/sekainook/web/         (Flutter Web 静态产物)
```

复用：`functions/`（全部业务）+ `migrations/`（建表 SQL）+ `_lib/*`（纯逻辑）。
新增：`server/`（适配层，约 300 行）+ `deploy/`（systemd / nginx / 备份）。

## 3. 兼容层契约（适配层必须实现的方法）

这一节是 `server/` 的验收标准，逐条对照现有调用点。

### 3.1 D1（`server/d1.ts`）

```ts
interface D1Database {
  prepare(sql: string): D1Stmt;
  batch(stmts: D1Stmt[]): Promise<D1Result[]>;   // 4 处调用，需在同一事务里
}
interface D1Stmt {
  bind(...values: unknown[]): D1Stmt;
  all<T>(): Promise<{ results: T[] }>;            // 7 处
  first<T>(): Promise<T | null>;                  // 含 RETURNING 的 upsert
  run(): Promise<{ meta: { changes: number } }>;  // 20 处，靠 meta.changes 判是否命中
}
```

实现要点：
- `first()` 必须能承接 `INSERT ... ON CONFLICT ... DO UPDATE ... RETURNING value`（`upload.ts:40`、`push/test.ts:98` 两处配额计数器）；
- `meta.changes` 用 `stmt.run().changes`；
- `batch()` 用一个事务包住，失败整体回滚（`settings.ts:104/419`、`notifications.ts:53`、`plans/index.ts:111`）；
- 打开 `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000; PRAGMA foreign_keys=ON;`
- 未绑定参数的 `first()`/`all()` 也要支持（现有代码全部 `.bind()`，但别假设）；
- 参数类型：`string | number | null | boolean`（boolean 要转 0/1）。

### 3.2 R2（`server/r2.ts`）

```ts
interface R2Bucket {
  get(key: string): Promise<{
    body: ReadableStream;
    httpMetadata?: { contentType?: string };
    httpEtag: string;
    writeHttpMetadata(headers: Headers): void;
  } | null>;
  put(key: string, body: ArrayBuffer | Uint8Array, opts?: { httpMetadata?: { contentType?: string } }): Promise<void>;
  delete(key: string | string[]): Promise<void>;          // 支持单 key 与数组
  list(opts: { prefix?: string; limit?: number; cursor?: string }): Promise<{
    objects: { key: string; uploaded: Date }[];
    truncated: boolean;
    cursor?: string;
  }>;
}
```

实现要点：文件路径做 base64url 或原样映射（key 只含 `tasks/<ts>-<uuid8>.<ext>`，无需转义，但要拒绝 `..`）；
`httpEtag` 用 `"${size}-${mtimeMs}"`；`list` 用目录遍历 + 按 key 排序，cursor 用「上一页最后一个 key」实现稳定分页（`orphans.ts:98` 依赖 `truncated` + `cursor` 防死循环）。

### 3.3 HTTP 入口（`server/index.ts`）

路由扫描规则（与 Pages 一致）：

| 文件 | 路由 |
|---|---|
| `functions/api/ledger/index.ts` | `/api/ledger` |
| `functions/api/ledger/[id].ts` | `/api/ledger/:id` |
| `functions/api/images/[[key]].ts` | `/api/images/*`（多段，`params.key` 是数组，调用方 `.join('/')`） |
| `functions/_middleware.ts` | 包在所有 `/api/*` 外层（只做 CORS + OPTIONS 204） |

- 只导出 `onRequest` / `onRequestGet` / `onRequestPost` / `onRequestPatch` / `onRequestDelete` / `onRequestPut` 的模块才是路由；
- `functions/_lib/**` 不挂路由；
- 请求体：`upload.ts` 用 `request.arrayBuffer()`，`others` 用 `request.json()`；
- 响应：`new Response(body, {headers})` 原样返回，`Response.json` 原生可用。

### 3.4 环境变量注入（`server/env.ts`）

```ts
env = {
  DB: createD1(DB_PATH),
  STARRYMIKU_BUCKET: createR2(R2_DIR),
  ADMIN_PASSWORD: process.env.ADMIN_PASSWORD,   // 测试期单独一个口令，别用线上同一个
  VAPID_PUBLIC_KEY: '',                          // 留空 → /api/push/key 返回 ready:false
  VAPID_SUBJECT: '',
  REMINDER_URL: '',                              // 留空 → 自检里推送类检查预期红
}
```

## 5. 代码落地

只把两个后端目录同步过去，**不要在服务器上拉整个仓库**（前端 `node_modules` 会白占几百 MB）：

```bash
# Windows 本机 → 服务器（PowerShell 也能跑 scp；rsync 可用 Git Bash / WSL）
scp -r E:\Git\SekaiNook\functions  sekainook@<IP>:/opt/sekainook/
scp -r E:\Git\SekaiNook\migrations sekainook@<IP>:/opt/sekainook/
# 之后改后端代码只需再同步这两个目录，然后 systemctl restart sekainook
```

服务器目录最终形状：

```
/opt/sekainook/
├── functions/          # 从仓库同步，不改
├── migrations/         # 从仓库同步，不改
├── server/             # 新增适配层（本方案 §3）
│   ├── index.ts
│   ├── d1.ts
│   ├── r2.ts
│   ├── env.ts
│   └── routes.generated.ts   # 由 scripts/gen-routes.mjs 生成（扫描 functions/）
├── scripts/gen-routes.mjs    # 新增
├── data/
│   ├── sekainook.db
│   └── r2/tasks/...
├── web/                # Flutter 构建产物（本地构建后 rsync 上来）
├── deploy/
│   ├── sekainook.service
│   ├── nginx-sekainook.conf
│   └── backup.sh
├── .env                # 600 权限
└── package.json        # better-sqlite3 + tsx
```

依赖只两个（服务器上自建 `package.json`，不继承仓库根那份 —— 根那份是前端 React 依赖）：

```bash
cd /opt/sekainook
npm init -y
npm i better-sqlite3 tsx
```

> **不要用 `node --experimental-strip-types` 直接跑 `functions/`**：现有代码是无扩展名 import
> （`import ... from '../../_lib/rules'`），Node 的 strip-types 解析不了。用 `tsx`（esbuild 转译）。
> 2G 机器跑 tsx 常驻约 100–150MB，够用；想再省可用 esbuild 预打包成单文件。

## 6. 数据：线上 D1 快照导入

### 6.1 导出（在你本机 Windows 上，不是服务器）

```powershell
cd E:\Git\SekaiNook
$env:HTTP_PROXY=''; $env:HTTPS_PROXY=''; $env:NO_PROXY='*'   # wrangler 走 D1 HTTP API，必须清代理

npx wrangler d1 export sekainook --remote --no-schema --output=snapshot-data.sql

# 传到服务器
scp snapshot-data.sql sekainook@<IP>:/tmp/
```

- `--no-schema`：只导数据（建表交给 `migrations/`，保证 schema 是最新口径）；
- 去掉 `--no-schema` 会连 `CREATE TABLE` 一起导，那份 schema 可能落后于 0007，不要用；
- 导出文件里会包含 `d1_migrations` 表的数据，见 §6.2 的处理；
- 想只导某几张表可以重复传 `--table family_ledger --table settings`（本项目表少，全导更省事）。

### 6.2 导入（服务器上）

```bash
cd /opt/sekainook

# ① 先建表：按编号顺序喂 migrations（幂等，可重复执行）
for f in migrations/0*.sql; do
  echo "== $f"
  sqlite3 data/sekainook.db < "$f"
done

# ② d1_migrations 是 wrangler 自己的表，本地库没有 → 先建出来，避免 INSERT 报错
sqlite3 data/sekainook.db "CREATE TABLE IF NOT EXISTS d1_migrations (
  id INTEGER PRIMARY KEY, name TEXT UNIQUE, applied_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP);"

# ③ 灌数据（出错不中断，因为 d1_migrations 之外不应有失败）
sqlite3 data/sekainook.db < /tmp/snapshot-data.sql

# ④ 校验行数（与线上对比：ledger / plans / notifications / settings / changelog / push_subscriptions）
sqlite3 data/sekainook.db "SELECT 'ledger', COUNT(*) FROM family_ledger
  UNION ALL SELECT 'plans', COUNT(*) FROM weekly_plans
  UNION ALL SELECT 'notif', COUNT(*) FROM notifications
  UNION ALL SELECT 'settings', COUNT(*) FROM settings
  UNION ALL SELECT 'changelog', COUNT(*) FROM changelog
  UNION ALL SELECT 'push', COUNT(*) FROM push_subscriptions;"
```

线上行数用 `npx wrangler d1 execute sekainook --remote --command "SELECT COUNT(*) FROM family_ledger"` 取，两边对上即可。

### 6.3 纪律

- 快照是**静态的**：测试站之后产生的流水不会回到线上，线上新增的也不会进测试站；
- 别在测试站用真实照片（`data/r2/` 会带上快照里的图片 key，但文件本身不在导出里 —— 需要图片就从 R2 手动 `wrangler r2 object get` 下来，或接受测试站图片全 404）；
- 记录导出时间，写进 `deploy/README`，避免以后分不清哪份是快照。

## 7. 前端构建（指向服务器）

**在本地构建，别在服务器上构建** —— Flutter Web 编译峰值内存 1.5G+，2G 机器极易 OOM。

```powershell
cd E:\Git\SekaiNook\app
flutter build web --release --no-pub --dart-define=API_BASE=http://<服务器公网IP>
node ..\scripts\stamp-web-version.mjs

# 传到服务器
scp -r build\web\* sekainook@<IP>:/opt/sekainook/web/
```

说明：
- `npm run web:build` 里写死 `API_BASE=https://sn.starrymiku.com`，测试站需要单独一条命令（或后续加 `web:build:test` 脚本，本次不动仓库）；
- IP + HTTP 下 Service Worker 不注册、PWA/推送不可用，页面本身正常；
- 同源访问，无跨域问题（`_middleware.ts` 仍会加 `Access-Control-Allow-Origin: *`，无害）。

### 8.3 `deploy/nginx-sekainook.conf`

```nginx
server {
    listen 80 default_server;
    server_name _;

    root /opt/sekainook/web;
    index index.html;
    client_max_body_size 8m;          # 图片上限 5MB + 表单开销

    # API：不缓存，转发本机 Node
    # ^~ 必不可少：否则下面那条「静态资源正则」会优先匹配以 .json 结尾的 API 路径
    location ^~ /api/ {
        proxy_pass http://127.0.0.1:8788;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
        add_header Cache-Control "no-store" always;
    }

    # Flutter Web：静态资源长缓存，其余交给 SPA
    location ~* \.(js|css|wasm|png|jpg|jpeg|webp|gif|svg|woff2|json)$ {
        expires 30d;
        add_header Cache-Control "public, max-age=2592000, immutable";
        try_files $uri =404;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
sudo cp deploy/nginx-sekainook.conf /etc/nginx/sites-available/sekainook
sudo ln -sf /etc/nginx/sites-available/sekainook /etc/nginx/sites-enabled/sekainook
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

## 9. 安全加固（**必做**，这是零鉴权后端暴露公网）

现有后端的设计前提是「家里人在同一 WiFi 下」：**接口零鉴权、CORS `*`、`/api/images/*` 匿名**。
放到公网 IP 上，就必须在外层补门。

| 措施 | 做法 | 说明 |
|---|---|---|
| 来源限制（最有效） | nginx `allow <家里公网IP>; deny all;` | 不影响 SPA（浏览器请求同源，源 IP 就是家里出口 IP）；家里 IP 变了要改 |
| 端口 | 只开 80/22；8788 绑 `127.0.0.1` | 别把 Node 直接暴露 |
| SSH | 密钥登录、`PermitRootLogin no`、`PasswordAuthentication no` | |
| 防火墙 | ufw / fail2ban | 国内扫描非常密集 |
| 口令 | 测试站用**新的** `ADMIN_PASSWORD` | 别复用线上口令，测试站被爆破不影响真实后台 |
| 数据 | 不放真实照片、必要时脱敏 | 快照里有流水内容，别长期公开 |

nginx 的 IP 白名单示例（加在 `server {}` 内）：

```nginx
allow 1.2.3.4;      # 家里宽带出口 IP
allow 127.0.0.1;
deny  all;
```

## 12. 已知差异（测试站 vs 线上）

| 能力 | CF 线上 | 国内云测试站 |
|---|---|---|
| 域名 / HTTPS | `https://sn.starrymiku.com` | `http://<IP>`（无备案域名，无 HTTPS） |
| 数据库 | D1（唯一真源） | SQLite 快照（独立，单向） |
| 图片 | R2（快照里只有引用，文件不全） | 本地磁盘 `data/r2/` |
| 21:30 提醒 | `workers/reminder` cron | 不跑（可后续用 systemd timer + web-push 复刻） |
| Web Push | 可用 | **不可用**（HTTP 非安全上下文） |
| PWA / Service Worker | 可用 | **不可用**（同上） |
| App 更新清单 | R2 `pub.starrymiku.com` | 不提供 |
| 自检 71 项 | 全绿 | 推送类预期红，其余应绿 |
| 数据一致性 | 实时 | 停在快照时点 |

## 13. 备份与回滚

```bash
# deploy/backup.sh（每天 03:00，保留 7 天）
#!/usr/bin/env bash
set -euo pipefail
D=/opt/sekainook/data
sqlite3 "$D/sekainook.db" ".backup '$D/backup-$(date +%F).db'"
find "$D" -name 'backup-*.db' -mtime +7 -delete
tar -czf "$D/r2-$(date +%F).tar.gz" -C "$D" r2
find "$D" -name 'r2-*.tar.gz' -mtime +7 -delete
```

```bash
# 装定时（root 的 crontab）
sudo crontab -e
# 0 3 * * * /opt/sekainook/deploy/backup.sh >> /var/log/sekainook-backup.log 2>&1
```

```bash
# 撤销测试站（线上不受影响）
```

4. 图片：继续本地目录 + 每日备份，或换 MinIO（2G 内存跑 MinIO 约 150MB，可接受但没必要）
5. 数据迁移：以 CF 为真源，最后一次 `d1 export` 后切自建；或反向以自建为主、D1 做备份
6. 运维：日志（journald 够用）、Uptime 监控、磁盘告警
7. **代码不分叉**：`functions/` 仍是唯一业务实现，`server/` 只是运行时适配层 —— 这是本方案最大的好处，两套环境不会漂

## 15. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 公网零鉴权，被扫到就能改账本/删照片 | **高** | nginx IP 白名单 + 安全组限源 + 测试期别放真实数据 |
| 快照被误回写线上 | 中 | 测试站数据库只读自用；线上 `wrangler` 命令只用于导出 |
| 2G 内存构建 Flutter Web OOM | 中 | 本地构建后 rsync（§7） |
| 服务器挂了丢测试数据 | 中 | 每日备份（§13）；本来也是快照副本 |
| 两套环境版本漂移 | 中 | 定期 `git pull` + 重跑 migrations；`functions/` 共享 |
| 家用公网 IP 变化导致白名单失效 | 低 | 临时加当前 IP；或用 SSH 隧道测 |
| 服务器 IP 被限速/封 | 低 | 换弹性公网 IP 或退回 CF |

### 16.2 已跑通的组件

- `/opt/sekainook`：仓库工作区（git 管理）+ `data/sekainook.db`（D1 快照副本）+ `data/r2/`（图片目录）+ `web/`（Flutter Web 产物）
- `/opt/flutter-sdk/flutter`：Flutter 3.47.7（与本地同版本），服务器可自行构建前端

- 数据：6 张业务表齐全，行数与线上快照一致；余额 610 / 1160（合计 1770）

### 16.3 更新方式（重点）

**服务器直连 GitHub 不可行**：`git ls-remote` 0.96s 成功，但 `git fetch` 大传输报
`GnuTLS recv error (-110): The TLS connection was non-properly terminated`（国内网络对
GitHub 大流量连接的干扰，小请求能过、大下载被掐）。因此改为**本地 push 到服务器裸仓库**，
只有增量传输，稳定可靠。

一次性初始化（已完成，换机器时照抄）：

```bash
# 本地：打 bundle（实测 6.9MB）传到服务器
git bundle create .snapshot/sekainook.bundle main
scp .snapshot/sekainook.bundle ubuntu@<IP>:/tmp/

# 服务器：从 bundle 建裸仓库（/opt 属 root，必须先 sudo mkdir + chown）
sudo mkdir -p /opt/sekainook.git && sudo chown ubuntu:ubuntu /opt/sekainook.git
git clone --bare /tmp/sekainook.bundle /opt/sekainook.git
rm -rf /opt/sekainook/.git          # 清掉之前误 `git init` 留下的空仓库
GIT_WORK_TREE=/opt/sekainook git --git-dir=/opt/sekainook.git checkout -f main

# 服务器：自动部署钩子（收到 push 即更新工作区并重启）
printf '#!/bin/sh\nGIT_WORK_TREE=/opt/sekainook git --git-dir=/opt/sekainook.git checkout -f main\nsudo -n /usr/bin/systemctl restart sekainook\n' \
  | sudo tee /opt/sekainook.git/hooks/post-receive >/dev/null
sudo chmod +x /opt/sekainook.git/hooks/post-receive
echo "ubuntu ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart sekainook" \
  | sudo tee /etc/sudoers.d/sekainook >/dev/null
sudo chmod 440 /etc/sudoers.d/sekainook
```

日常更新（本地一条命令）：

```powershell
cd E:\Git\SekaiNook
git add -A
git commit -m "feat: ..."
git push tencent main      # 服务器自动 checkout + 重启后端
```

> `tencent` 是本地给服务器裸仓库起的 remote 名：
> `git remote add tencent ssh://ubuntu@<IP>/opt/sekainook.git`
>
> 注意：**前端 `web/` 不在这条链路里** —— 它是 Flutter 构建产物，需在 `deploy.sh` 里另行构建
> （或在本地构建后同步）。后端改动 push 即生效，前端改动仍需单独构建。

### 16.5 已知未解决 / 注意事项

1. 数据库里老图片 URL 指向 `https://sn.starrymiku.com/...`，测试站会回源线上加载（能显示但慢）
2. 提醒功能仍由 CF Worker 驱动（读线上 D1），测试站自身不产生推送
3. 两层密码别混：nginx Basic Auth 是 `family` / `3398`；页面内管理员口令是 `sekainook-test`
4. 内核 6.8.0-147 已安装并**已于 2026-10-30 重启生效**（`uname -r` = `6.8.0-147-generic`）
5. 服务器 node 依赖已修正到 `server/node_modules`，systemd `ExecStart` 指向
   `/opt/sekainook/server/node_modules/tsx/dist/cli.mjs`（早先装在根目录那套已废弃）
6. **git hook 会导出 `GIT_DIR` / `GIT_WORK_TREE`** 给子进程，`flutter` / `dart` 继承后会在
   `app/` 目录报 `fatal: not a git repository: '.'`（不影响构建，但日志很吵）。
   `server/deploy.sh` 开头已 `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE GIT_PREFIX`，别再删掉
7. Flutter 首次在某环境运行会 `Building flutter tool...`（约 30s），之后走缓存

### 16.6 备份与恢复

**自动备份**：`/etc/cron.d/sekainook-backup` 每天 03:00 跑 `server/backup.sh`
- `db-<时间戳>.sqlite3`：SQLite `.backup` 在线热备（不锁库）
- `r2-<时间戳>.tar.gz`：图片目录
- 保留最近 14 天，存 `/opt/sekainook-backups`

**手动备份**：

```bash
/opt/sekainook/server/backup.sh
```

**恢复数据库**（先停服务再覆盖）：

```bash
sudo systemctl stop sekainook
cp /opt/sekainook-backups/db-20261030-171131.sqlite3 /opt/sekainook/data/sekainook.db
sudo systemctl start sekainook
```

**恢复图片**：

```bash
tar -xzf /opt/sekainook-backups/r2-20261030-171131.tar.gz -C /opt/sekainook/data
```
